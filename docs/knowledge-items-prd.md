# 知识条目 PRD

> 文档状态：基于当前代码实现整理。本文区分“当前已实现”和“后续建议”，不将规划能力描述为已上线功能。

## 1. 产品定位

知识条目用于以结构化表格维护品牌可被 AI 引用的业务事实，例如产品、服务、解决方案、案例和常见问题。每条记录由系统 ID、名称、正文、来源链接和标签等字段组成，可在博客文章创作和 Copilot 对话中按需选择。

知识条目与“知识资料”不同：

| 对象 | 当前用途 | 数据形态 |
| --- | --- | --- |
| 知识条目 | 维护产品、服务、案例等单条业务事实 | 可配置字段的表格行 |
| 知识资料 | 管理上传的文件、分块内容和资料解析状态 | 文件元数据与文本分块 |

## 2. 范围与入口

- 入口：左侧导航“品牌知识 / 知识条目”。导航配置位于 `src/data/navigation.js` {左侧导航模块和可用入口定义}，页面挂载位于 `src/components/MainContent.jsx` {根据当前导航项渲染业务页面}。
- 项目维度：切换项目后，页面重新读取该项目的知识条目草稿，退出编辑态并清除当前校验信息。
- 外部定位：文章页面传入条目 ID 时，页面会定位到对应预设类型并高亮匹配行；目前定位依据是演示数据条目的标题匹配。
- 支持语言：页面文案来自 `src/i18n/messages.js` {中英文界面文案字典}。

## 3. 用户目标

1. 按业务类型集中维护可复用的品牌知识。
2. 用表格快速浏览、录入和修订知识记录。
3. 根据业务需要创建自定义知识表和字段。
4. 在文章创作或 Copilot 对话中选择有限数量的知识条目作为上下文。

## 4. 当前信息架构

### 4.1 知识类型

页面左侧将类型分为“系统预设”和“自定义”两组，均可展开或折叠。

当前系统预设类型及其必填字段如下：

| 类型 ID | 页面名称 | 必填字段 | 其他主要字段 |
| --- | --- | --- | --- |
| `products` | 主营产品 | 产品名称、产品描述 | 别名、产品链接、标签 |
| `services` | 主要服务 | 服务名称、服务描述 | 服务链接、标签 |
| `solutions` | 解决方案 | 方案名称、方案内容 | 目标场景、关联服务、标签 |
| `cases` | 公司案例 | 案例名称、案例摘要 | 所属行业、案例链接、标签 |
| `faqs` | FAQ | 问题、回答 | FAQ 链接、标签 |

所有类型都有只读的 `knowledgeId` {知识条目系统编号字段}。预设类型的字段结构不可在页面内增删；自定义类型可新增和删除非系统字段。

### 4.2 数据模型

知识条目草稿采用下列结构：

```js
{
  types: [
    {
      id: 'products',
      preset: true,
      prefix: 'prod',
      nameFieldKey: 'productName',
      fields: [
        { key: 'knowledgeId', type: 'system', readOnly: true, aiRole: 'id' },
        { key: 'productName', type: 'shortText', required: true, aiRole: 'name' },
        { key: 'description', type: 'longText', required: true, aiRole: 'body' }
      ]
    }
  ],
  rows: {
    products: [
      {
        id: 'products-row-001',
        knowledgeId: 'ki-prod-001',
        cells: { productName: '示例产品', description: '示例说明' }
      }
    ]
  }
}
```

字段定义来源于 `src/services/knowledgeItemStore.js` {知识类型、字段、行数据和持久化的统一数据层}。字段类型目前支持：

- `shortText` {短文本字段}
- `longText` {长文本字段}
- `url` {HTTP 或 HTTPS 链接字段}
- `tags` {按逗号、中文逗号或换行拆分的标签数组}
- `multiSelect` {按标签数组保存的多选字段}
- `number` {保存时转换为数值的字段}

`aiRole` {字段给 AI 上下文转换使用的语义标记} 目前用于识别名称、正文、来源链接和标签等关键内容。

## 5. 当前功能需求与实现规则

### 5.1 浏览知识表

- 选择左侧类型后，在右侧查看对应表格。
- 表格支持“全部字段”和“必填字段”两种视图；必填字段视图保留系统 ID 和所有必填字段。
- 浏览态不足 12 行时，页面仅补充空白视觉行，不会创建真实数据。
- 点击单元格后，顶部公式栏显示该单元格坐标、字段名称和内容；浏览态公式栏只读。
- 从文章页面跳转并携带 `focusItemId` {外部传入的知识条目定位 ID} 时，匹配行以高亮样式显示。

### 5.2 编辑和保存条目

1. 点击“编辑”进入编辑态。
2. 已保存行会深拷贝到编辑草稿，并在表格底部追加 8 行空草稿行，方便连续录入。
3. 可直接编辑非只读单元格，也可在公式栏编辑当前选中单元格。
4. 点击“保存”时执行校验和标准化；校验成功后整体保存当前类型的行数据并显示成功提示。
5. 空白草稿行不会保存；填写过任意可编辑字段的草稿行会成为正式记录。
6. 新记录保存时生成行 ID 和类型内递增的 `knowledgeId`，格式为 `ki-<类型前缀>-<三位序号>`。

当前页面没有“删除知识行”操作，也没有行排序、批量导入或单条目详情页。

### 5.3 行数据校验

| 规则 | 当前行为 |
| --- | --- |
| 必填字段 | 为空时标记对应单元格错误，并显示页面级校验提示。 |
| URL 字段 | 空值可保存；非空值必须是 `http` 或 `https`。 |
| 标签和多选 | 输入按逗号、中文逗号、换行拆分，去除空值后保存为数组。 |
| 数字字段 | 非空文本在保存时转换为 `Number`。 |
| 文本字段 | 保存时去除首尾空白。 |
| 系统 ID | 页面只读，不允许人工编辑。 |

### 5.4 放弃编辑

- 编辑内容与已保存行不一致时，取消编辑或切换知识类型会弹出“放弃更改”确认框。
- 选择“继续编辑”保留当前编辑态；确认放弃后丢弃未保存行数据并退出编辑态。
- 当前脏数据比较只覆盖行数据，不包含自定义类型抽屉中的未保存配置。

### 5.5 新建自定义知识类型

1. 点击左侧“新建类型”打开右侧抽屉。
2. 填写类型名称、可选描述和字段列表。
3. 首个字段是名称字段，固定为必填短文本，字段名称最长 20 个字符，不能删除或改为其他类型。
4. 其余字段可选择字段类型和是否必填，可在抽屉内新增或删除。
5. 保存前校验类型名称、字段名称、字段类型和字段名称重复。
6. 保存成功后创建自定义类型、初始化空行集合、切换到新类型，并显示成功提示。

自定义类型 ID 由名称和时间戳生成；其首字段会被标记为 `aiRole: 'name'` {供 AI 转换时作为条目名称}，标签字段会标记为 `aiRole: 'tags'` {供 AI 转换时作为标签}。

### 5.6 自定义字段管理

- 仅在“编辑”状态下，且当前为自定义类型时，显示“新增字段”操作。
- 新增字段时校验字段名称、字段类型和与现有字段的重名。
- 删除字段前必须二次确认；删除后会从类型定义、已保存行和当前编辑草稿中移除该字段的所有值。
- 不允许删除系统 ID 字段；若只剩一个可编辑字段，也不允许继续删除。
- 预设类型不提供字段新增或删除入口。

### 5.7 导出按钮

页面展示“导出”按钮，但当前按钮没有绑定点击处理，因此不会生成或下载文件。该能力应标记为未实现，不应在对外说明中承诺可导出。

## 6. 与文章创作和 Copilot 的关系

### 6.1 文章 AI 创作

文章任务创建页通过 `getKnowledgeSelectionData(project)` {将知识条目和资料转换为选择器数据} 读取当前项目的知识条目。

- 选择弹窗按知识类型浏览条目，可多选；弹窗搜索仅搜索“知识类型名称和描述”，不搜索条目正文、标签或标题。
- 创建任务时，当前选中的条目对象会作为 `knowledgeItems` {文章任务输入中的知识条目快照} 写入任务数据。
- 任务创建后，后续生成流程使用该任务快照，不会自动跟随知识条目表后续修改。

### 6.2 Copilot 对话

Copilot 允许从知识条目选择器选择条目，并由 `buildCopilotKnowledgeAttachments()` {将已选条目压缩为聊天附件上下文} 生成附件。

- 单次最多 8 个知识条目或资料附件。
- 单个附件最多 12,000 个字符，所有附件合计最多 48,000 个字符。
- 结构化知识条目会拼接标题、正文摘要、标签和来源链接作为聊天上下文。
- 当前流程是“显式选择后随消息提交”的上下文拼接，不是自动检索或向量召回。

## 7. 数据来源与存储边界

### 7.1 初始数据

首次读取时，预设知识类型和演示知识记录来自 `src/data/demo/database/` {随前端构建打包的固定演示数据库}。数据层会将演示项目中的产品、服务、解决方案、案例和 FAQ 映射为对应表格行。

### 7.2 当前持久化方式

知识条目通过 `src/services/demoSessionStore.js` {按项目和表名管理浏览器会话快照} 写入浏览器 `sessionStorage` {当前标签页有效的浏览器会话存储}：

```text
content-studio-demo-session:v<数据库版本>:<项目ID>:knowledgeItems
```

- 同一项目的类型定义和全部行数据保存在同一个快照中。
- 关闭标签页后，`sessionStorage` 数据会丢失；下次读取会回退到演示种子数据。
- 切换项目时数据按项目 ID 隔离。
- 数据库版本不匹配或快照格式异常时，旧快照会被删除并回退到种子数据。
- 当前知识条目不会写入 Node 后端、EdgeOne `context.store` {EdgeOne 服务端键值存储}、关系型数据库或向量数据库。

## 8. 当前限制与未实现项

1. 没有远端 CRUD API {创建、读取、更新、删除接口}，无法多用户协作或跨设备持久化。
2. 没有条目级删除、复制、排序、分页、批量编辑、批量导入、真实导出和操作审计。
3. 没有全文检索、标签筛选或按条目内容搜索；选择弹窗只支持类型搜索。
4. 没有条目版本、发布状态、草稿状态、权限控制或并发冲突处理。
5. 没有自动同步到 AI 知识库、embedding {把文本转换为向量表示的索引过程}、向量检索或引用溯源能力。
6. “知识资料”的网页解析与文件分块是另一条链路；知识条目页不会抓取 URL，也不会从文件中自动生成条目。

## 9. 后续后端化需求

以下为后续接入后端时的需求，不属于当前已实现范围：

| 优先级 | 需求 | 说明 |
| --- | --- | --- |
| P0 | 项目级类型和条目 CRUD API | 将当前 `types + rows` 会话快照迁移为后端可持久化数据。 |
| P0 | 稳定 ID 与并发控制 | 后端生成不可变条目 ID、更新时间和版本号，避免多端覆盖。 |
| P0 | 条目删除与审计 | 支持软删除、恢复和操作记录，避免误删不可追溯。 |
| P1 | 查询接口 | 支持按类型、名称、标签、更新时间搜索与分页。 |
| P1 | 文章任务快照 | 创建文章任务时保存已选条目的版本快照和来源信息。 |
| P1 | Copilot 上下文服务 | 在服务端统一执行附件长度限制、权限校验和上下文拼接。 |
| P2 | 索引与检索 | 对已发布条目构建向量索引，支持语义检索、引用来源和重建索引。 |
| P2 | 导入导出 | 提供模板下载、校验预览、CSV/XLSX 导入和真实导出。 |

## 10. 验收标准

### 10.1 当前实现验收

- 能在两个演示项目中进入“知识条目”，并看到对应预设类型和演示行。
- 编辑预设类型行后保存成功，刷新当前标签页前仍能读取该项目快照。
- 必填字段为空、URL 格式错误时，保存被阻止并显示对应错误。
- 取消或切换类型时，如存在未保存行变更，会出现放弃确认。
- 可创建自定义类型；首字段必须是必填短文本且字段名不能超过 20 个字符。
- 可为自定义类型新增字段；删除字段后所有对应单元格值同步消失。
- 文章 AI 创作和 Copilot 选择器均能显示当前知识条目并可选中。

### 10.2 后端化验收

- 知识条目在刷新、重新打开浏览器和跨设备登录后仍可读取。
- 两个用户同时修改同一条目时，系统能返回版本冲突或提供明确覆盖策略。
- 删除、导入和导出操作有明确的权限、校验、失败反馈与可追溯记录。
- Copilot 和文章任务引用的条目可定位到稳定 ID、版本和来源。
